# PLC S7-1200 (CPU 1215C) — esclavo de E/S del tablero

El PLC barre la matriz 8x8, lee el botón de confirmación y el e-stop, y
comanda la baliza. La Raspberry Pi lee/escribe el DB por Ethernet con
`python-snap7` (protocolo S7). El PLC **no decide nada del juego**: es un
esclavo de E/S con señalización local.

## 1. Configuración de la CPU en TIA Portal

1. **IP fija** en la misma subred que la Pi (default del backend:
   `192.168.0.20/24` — configurable con `CHESS_PLC_HOST`).
2. **Habilitar PUT/GET**: Propiedades de la CPU → Protección & Seguridad →
   Mecanismos de conexión → ✔ "Permitir acceso vía comunicación PUT/GET…".
3. **Nivel de protección**: "Acceso completo (sin protección)" o con
   contraseña solo para HMI/TIA (PUT/GET debe quedar permitido).
4. **Filtro de entradas**: Propiedades → DI 14/DQ 10 → Entradas digitales →
   canales I0.0–I0.7 → tiempo de filtro **0.8 ms** (default 6.4 ms; con el
   default el barrido no llega a ver las columnas).

## 2. Cableado (E/S onboard del 1215C)

| Señal | Borne | Descripción |
|---|---|---|
| Filas 1–8 (salidas) | Q0.0–Q0.7 | Energizan una fila de sensores por vez |
| Columnas a–h (entradas) | I0.0–I0.7 | Leen los sensores de la fila activa |
| Botón confirmar jugada | I1.0 | NA, a 24 V |
| Contacto aux. e-stop | I1.1 | NC (1 = e-stop OK) |
| Baliza verde (turno humano) | Q1.0 | |
| Baliza roja (robot en movimiento) | Q1.1 | |

- Cada sensor reed lleva **diodo en serie** (p. ej. 1N4148): ánodo hacia la
  fila (Q), cátodo hacia la columna (I). Sin diodos hay lecturas fantasma
  con 3+ piezas en "L".
- 1215C DC/DC/DC: salidas a transistor 24 V. La baliza amarilla no tiene
  salida propia: el estado "error" se señaliza con **verde+rojo parpadeando**
  (o agregar una SM si se quiere amarillo físico).

## 3. Bloque de datos `ChessIO` (DB1)

Crear DB global **con "Acceso optimizado al bloque" DESACTIVADO** (clic
derecho → Propiedades → Atributos), si no snap7 no puede direccionarlo.

```
ChessIO (DB1, no optimizado)
┌──────────┬───────────────┬─────────────────────────────────────────────┐
│ Offset   │ Tipo          │ Contenido                                   │
├──────────┼───────────────┼─────────────────────────────────────────────┤
│ DBB0..7  │ ARRAY[0..7]   │ Ocupación: byte n = fila n+1;               │
│          │ OF BYTE       │ bit m = columna (a=0 … h=7)                 │
│ DBB8     │ BYTE          │ Panel: bit0 = botón, bit1 = e-stop OK       │
│ DBB9     │ BYTE          │ Reservado                                   │
│ DBW10    │ WORD          │ Heartbeat (se incrementa por barrido)       │
│ DBB12    │ BYTE          │ Status (escribe la Pi): 0 idle, 1 humano,   │
│          │               │ 2 robot, 3 error/resync, 4 fin de partida   │
│ DBB13    │ BYTE          │ Reservado                                   │
└──────────┴───────────────┴─────────────────────────────────────────────┘
```

Interfaz del DB en TIA:

```
board     : Array[0..7] of Byte;
panel     : Byte;
reserved1 : Byte;
heartbeat : Word;
status    : Byte;
reserved2 : Byte;
```

## 4. Programa del PLC

### OB30 — Interrupción cíclica, **5 ms** (barrido de matriz)

Una fila por ciclo: se lee la fila que quedó energizada los últimos 5 ms
(señal ya asentada) y recién después se conmuta a la siguiente.

```scl
// Variables estáticas del OB (o en un DB de instancia):
//   row : Int := 0;

// 1. Leer las columnas de la fila actualmente energizada (estable hace 5 ms)
"ChessIO".board[#row] := %IB0;

// 2. Avanzar a la próxima fila
#row := (#row + 1) MOD 8;

// 3. Energizar solo esa fila
%QB0 := SHL(IN := BYTE#16#01, N := INT_TO_USINT(#row));

// 4. Heartbeat: un incremento por barrido completo
IF #row = 0 THEN
    "ChessIO".heartbeat := "ChessIO".heartbeat + 1;
END_IF;
```

Barrido completo: 8 filas × 5 ms = 40 ms → **25 Hz**, dentro de la spec
(≥ 20 Hz). El debounce lo hace la Pi (3 lecturas estables).

### OB1 — Ciclo libre (panel y baliza)

```scl
// Panel → DB
"ChessIO".panel.%X0 := %I1.0;   // botón de confirmación
"ChessIO".panel.%X1 := %I1.1;   // e-stop OK (contacto NC)

// Status (lo escribe la Pi) → baliza
CASE BYTE_TO_INT("ChessIO".status) OF
    1:  // turno humano
        %Q1.0 := TRUE;  %Q1.1 := FALSE;
    2:  // robot en movimiento
        %Q1.0 := FALSE; %Q1.1 := TRUE;
    3:  // error / resync: ambas parpadeando
        %Q1.0 := "Clock_1Hz";  %Q1.1 := "Clock_1Hz";
    4:  // fin de partida: verde parpadeando
        %Q1.0 := "Clock_1Hz";  %Q1.1 := FALSE;
    ELSE // idle
        %Q1.0 := FALSE; %Q1.1 := FALSE;
END_CASE;
```

(`Clock_1Hz`: activar la "Marca de ciclo" en Propiedades de la CPU →
Marcas de sistema y de ciclo, p. ej. %M0.5.)

## 5. Lado Raspberry Pi

```sh
# En /etc/systemd/system/chess-backend.service:
Environment=CHESS_DRIVER=s7
Environment=CHESS_PLC_HOST=192.168.0.20
# Opcionales: CHESS_PLC_RACK=0  CHESS_PLC_SLOT=1  CHESS_PLC_DB=1

sudo systemctl daemon-reload && sudo systemctl restart chess-backend
```

Verificación rápida desde cualquier PC de la red:

```sh
curl http://192.168.0.10:8000/api/status
# → "plc": {"alive": true, "heartbeat": N creciente, "estop_ok": true, ...}
```

- `alive: false` → el heartbeat no avanza: PLC en STOP o OB30 no cargado.
- Error de conexión al arrancar → revisar PUT/GET, IP, o DB optimizado.
- El botón físico dispara la confirmación de jugada directamente (PanelLink);
  la baliza cambia sola con la fase de la partida.
